# Risks — agencyBRIDGE

| ID | Risk | Impact | Likelihood | Mitigation | Status |
|---|---|---|---|---|---|
| R-001 | Authentication is client-side only. `roleContext.tsx` compares a SHA-256 digest of the submitted password against a digest compiled into the bundle. Anyone can read the digests, bypass the check in devtools, or set `localStorage` directly. The app is live at a public URL. | Critical | Certain (it is not a control) | Move verification server-side, **or** password-protect the deployment and `noindex` it as an explicit demo. Decision pending (D-006). | **Open — release blocking** |
| R-002 | `clearAuditLog` enforces an admin role in the browser, which any user can satisfy. | Medium | High | Clearing is now itself audited (a genesis entry records who cleared and how many entries were discarded), so erasure is visible. Real enforcement requires R-001. | Mitigated, not resolved |
| R-003 | Marketing claims "audit logging meeting CMS 42 CFR requirements", but the log lives in `localStorage`. It detects mutation of retained entries; it cannot survive a cleared browser profile and is not an audit trail of record. | High | High | Chain integrity is now real (AUDIT-001). The **claim** still overstates it — either move the log server-side (append-only) or soften the copy. | Open |
| R-004 | Retention cap discards the oldest entries at 2,000. Deleting the head of a client-side chain is undetectable in principle. | Medium | Medium | `verifyAuditIntegrity` now reports `truncated` rather than a false tamper alarm, and the limit is documented in `auditLog.ts`. Full fix requires server-side storage. | Mitigated |
| R-005 | Test coverage is narrow: 5 of 14 `src/lib` modules (`auditLog`, `csv`, `dataScope`, `sha256`, `shortPayDetector`) and none of the 26 page components. Regressions in UI logic would not be caught. | Medium | Medium | 120 tests now cover the security- and money-critical paths. Extend to `emailCampaignData`, `medicareKnowledge`, and component smoke tests. | Open |
| R-006 | Landing hero and OG/Twitter share images are hot-linked from `vibe.filesafe.space`, a third-party CDN outside the project's control, with no provenance or licence record. | Medium | Medium | Re-host as owned assets under `public/` and record provenance in `brand/BRAND-PACKAGE.md`. | Open |
| R-007 | Adversarial review has covered `src/lib` logic only. The 26 page components — including untrusted-input surfaces such as the knowledge base and email campaign builder — have not been red-teamed. | Medium | Medium | Schedule a page-layer red-team pass; treat any finding as a regression-test target. | Open |
| R-008 | agencyBRIDGE is not listed in `build-contract-os/registry/PROJECT-REGISTRY.yaml`, so the portfolio control plane does not know it is governed. | Low | Certain | Registry entry must be added upstream; this session has read-only access to that repo (D-002). | Open — needs upstream write |
| R-009 | Contract and repository drift: the local working branch was stale against `origin/main` at session start. | Low | Medium | Reconcile on every agent entry; `RESUME.md` protocol followed and branch reset before any edit. | Mitigated |
| R-010 | Two tabs logging at the same moment each read-modify-write the whole log in `localStorage`, so one tab's entry can be silently overwritten. Verification still passes, because the surviving chain is internally consistent. | Medium | Low | Inherent to a synchronous `localStorage` append; the Web Locks API is async and `logAudit` is synchronous by necessity (D-003). Server-side append-only storage resolves it along with R-003. | Open |
